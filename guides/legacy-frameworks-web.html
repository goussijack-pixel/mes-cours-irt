01

Bibliothèque vs Framework & Inversion de Contrôle (IoC)

La différence fondamentale qui structure l'architecture logicielle moderne.

Bibliothèque (Library)

Tu contrôles le flux. Ton code appelle la bibliothèque quand il en a besoin (ex: Lodash, D3.js, Axios).

Framework (IoC)

Le framework contrôle le flux. Il appelle ton code selon des conventions strictes ("Ne nous appelez pas, nous vous appellerons").

Voir le détail théorique (Inversion de contrôle, Design Patterns & Routing)

1. Inversion of Control (IoC) : Le framework fournit le squelette de l'application et orchestre l'exécution. Le développeur ne fait qu'implémenter les points d'extension (contrôleurs, gestionnaires d'événements, hooks).

2. Injection de Dépendances (DI) : Mécanisme central dans les frameworks comme Spring Boot, NestJS ou Laravel où le framework instancie et injecte automatiquement les services dans les constructeurs.

Voir le détail théorique (Virtual DOM, useEffect & Props Drilling)

1. Virtual DOM & Algorithme de Réconciliation : React maintient une copie légère de l'arbre DOM en mémoire JavaScript. Lors d'un changement d'état, il calcule la différence minimale (Diffing Algorithm en $O(N)$) et applique uniquement les modifications nécessaires au vrai DOM navigateur.

2. Hook useEffect : Gère les effets de bord (appels API asynchrones, abonnements, timers). Le tableau de dépendances [dep] contrôle quand l'effet doit se réexécuter.

1. Avantage Stateless : Le serveur d'API n'a pas besoin de stocker les sessions en mémoire RAM ou en base de données. Il lui suffit de vérifier mathématiquement la signature du token à chaque requête.

2. Sécurité du Token : Le payload n'est PAS chiffré, il est seulement encodé en Base64Url. Il ne faut JAMAIS y stocker de mot de passe ni de donnée ultra-confidentielle.
