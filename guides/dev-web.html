TP PHP/MySQL procédural : site de génération de cartes d'étudiant avec QR code

L1 IRT
1

Énoncé au propre

TP de PHP/MySQL (L1 IRT 2023-2024), classé dans les ressources de L2. À rendre le 04/07/2024.

Réaliser un site qui génère des cartes d'étudiant. Informations sur la carte : matricule, nom, prénom, date et lieu de naissance, filière, classe, contact, photo, et un QR code contenant le matricule et un lien vers la carte (affichée dans une nouvelle fenêtre ou une fenêtre modale).

  1. Le site comprend : une bannière (logo, nom de l'école, zone de recherche) ; un menu (Accueil, Qui sommes-nous, Ajouter étudiant, Afficher étudiants, Nous contacter) ; un pied de page.
  2. Contenu des rubriques :
    • Accueil : présentation de l'école et de la L1 IRT ;
    • Qui sommes-nous : membres du groupe et rôle de chacun ;
    • Ajouter étudiant : formulaire de saisie ;
    • Afficher étudiants : tableau (noms, classe, contact, icône qui ouvre la carte dans une fenêtre) ; le nom est un lien vers le formulaire de mise à jour ; des cases à cocher et un bouton pour supprimer plusieurs étudiants ;
    • Nous contacter : formulaire d'envoi de mail (expéditeur, objet, message), avec l'adresse du destinataire dans un champ caché.

Contrainte : ni framework backend, ni programmation orientée objet. Uniquement de la programmation procédurale.

Corrigé détaillé

Essaie d’abord seul, puis ouvre chaque partie pour comparer.

Partie I – Q1 et Q2

1. Angular est un framework frontend open source de Google, écrit en TypeScript. Il sert à construire des applications web monopages (SPA) : la page ne se recharge pas, et l'interface se met à jour dynamiquement. Il fournit les composants, le routage, les formulaires, l'injection de dépendances et le client HTTP.

2. Les composants sont les briques de l'interface. Chacun regroupe :

  • une classe TypeScript (les données et la logique) ;
  • un template HTML (l'affichage) ;
  • des styles CSS.

L'application est un arbre de composants réutilisables (en-tête, liste, carte…).

Partie I – Q3 et Q4

3. Déclarer un composant : avec le décorateur @Component, ou en le générant avec ng generate component nom.

Il faut ensuite le déclarer dans le module (declarations), ou mettre standalone: true depuis Angular 15.

4. Le template est le HTML enrichi (interpolation {{ }}, directives, liaisons) qui décrit la vue du composant. Il est défini soit dans un fichier séparé (templateUrl), soit directement dans le décorateur (template: '<h1>…</h1>').

Partie I – Q5 à Q7

5. Directives structurelles

  • *ngIf ajoute ou retire l'élément selon une condition.
  • *ngFor répète l'élément pour chaque élément d'un tableau.
  • Depuis Angular 17, on peut aussi écrire @if et @for.

6. Une propriété est une variable déclarée dans la classe, éventuellement typée : titre: string = 'Mes tâches'; ou compteur = 0;. Elle est utilisable dans le template.

7. Les événements se lient avec des parenthèses : (click)="addTask()", (keyup.enter)="addTask()", (input)="...". La méthode est appelée à chaque événement ; on peut lui passer $event.

PHP orienté objet : Compte, virement, Client multi-comptes, BanqueInteractive

2h30L2 IRT
1

Énoncé au propre

Contrôle terminal du module PHP — ESGIS, L2 IRT.

Modélisation du fonctionnement d'une banque. Chaque classe est écrite dans un fichier séparé. Un fichier index.php teste chaque classe au fur et à mesure.

  1. Classe Compte : deux attributs privés (numéro, solde) et quatre méthodes : depot, retrait, getSolde() et afficherSolde().
  2. Virement : ajouter une méthode qui vire une somme vers un autre compte (arguments : la somme et le compte destinataire).
  3. Classe Client : trois attributs privés (numéro, nom, compte) ; méthodes getSolde (solde de son unique compte) et afficherSolde.
  4. Nom du client : un constructeur qui attribue un nom.
  5. Plusieurs comptes : remplacer le compte par un tableau comptes, ajouter l'attribut nbComptes et la méthode ajouterCompte ; getSolde renvoie alors la somme des soldes.
  6. Classe BanqueInteractive : entre autres ajouterClient, une méthode qui affiche le bilan de tous les comptes d'un client, et afficherBilan(), qui affiche le bilan général de tous les clients.
2

Corrigé détaillé

Essaie d’abord seul, puis ouvre chaque partie pour comparer.

1 et 2 – Compte.php
Encapsulation

Les attributs sont privés : on ne peut pas écrire $c->solde = 1000000 depuis l'extérieur. On passe obligatoirement par les méthodes, qui contrôlent les opérations (pas de retrait au-delà du solde, pas de dépôt négatif).

Le virement

Il faut réutiliser retrait() et depot(), pas modifier les soldes directement. Ainsi, un virement impossible (solde insuffisant) échoue proprement, sans créer d'argent.

3 à 5 – Client.php (version finale à plusieurs comptes)

Version de la question 3 (un seul compte) : un attribut private Compte $compte, et getSolde() renvoie $this->compte->getSolde().

6 – BanqueInteractive.php et index.php
Vérification

PHP n'est pas installé sur ce poste. Cette sortie a été obtenue en exécutant la même logique transposée en JavaScript (mêmes classes, mêmes contrôles). Le code PHP, lui, n'a pas été exécuté. Les contrôles « retrait de 80 000 refusé » et « dépôt négatif refusé » ont aussi été vérifiés.

Les relations entre les classes
  • Client contient des Compte : c'est une agrégation.
  • BanqueInteractive contient des Client.
  • Chaque classe a une seule responsabilité : c'est ce que le correcteur regarde.

Chapitre 1 sur 8

Module 0 — Comment marche un site web

  • Le front-end tourne dans le navigateur : HTML (le squelette), CSS (l'apparence), JavaScript (le comportement). Angular, React, Vue sont des frameworks front-end.
  • Le back-end tourne sur le serveur : il reçoit la requête, lit la base de données, fabrique la réponse. PHP (avec Laravel ou Symfony) ou JavaScript (avec Node.js/Express) sont des choix courants.
  • Ils parlent en HTTP : GET pour lire, POST pour envoyer un formulaire, PUT/DELETE dans les API.
Chapitre 2 sur 8

Module 1 — HTML et CSS

Les balises qui structurent

header, nav, main, section, article, footer (structure sémantique) ; h1…h6, p, a, img, ul/li, table/tr/td ; formulaires : form (action = où envoyer, method = get ou post), input (type text, email, password, date, file, hidden pour un champ caché), select, textarea, button.

Un sélecteur (nav a, .classe, #id), des propriétés ; flexbox et grid pour la mise en page ; @media pour s'adapter au téléphone (responsive).

Chapitre 3 sur 8

Module 2 — JavaScript dans la page

Le trio du DOM

Sélectionner un élément (querySelector), écouter un événement (addEventListener("click", …)), modifier la page (textContent, classList, appendChild). Pour ouvrir la carte dans une nouvelle fenêtre : window.open("carte.php?id=12", "carte", "width=420,height=300").

Chapitre 4 sur 8

Module 3 — PHP : les bases côté serveur

  • Les variables commencent par $ ; le point . concatène ; les tableaux s'écrivent [ ].
  • Les données d'un formulaire arrivent dans $_POST['nom'] (méthode post) ou $_GET['id'] (dans l'URL).
  • include "entete.php"; réutilise un morceau de page sur tout le site.
Chapitre 5 sur 8

Module 4 — PHP objet : Compte, Client, Banque

C'est le sujet du CT et du rattrapage. Une classe décrit un type d'objet ; ses attributs privés ne sont modifiables que par ses méthodes (encapsulation).

Le virement réutilise retrait et dépôt

Pas de code dupliqué : virement appelle retrait (qui vérifie le solde) puis depot du compte destinataire. Le total du client ne change pas : l'argent passe d'un compte à l'autre.

Chapitre 6 sur 8

Module 5 — PHP et MySQL avec PDO

Deux règles de sécurité non négociables
  • Requêtes préparées (prepare + execute avec des ?) : elles empêchent l'injection SQL.
  • htmlspecialchars sur tout ce qui vient d'un utilisateur avant de l'afficher : il empêche l'injection de JavaScript (XSS).

Et ne laisse jamais un mot de passe de base de données dans un dépôt public.

Le CRUD complet : Create (INSERT), Read (SELECT), Update (UPDATE … WHERE id = ?), Delete (DELETE … WHERE id = ?). Pour la photo : <input type="file">, enctype="multipart/form-data" sur le formulaire, puis move_uploaded_file().

Chapitre 7 sur 8

Module 6 — Angular (framework front-end)

Angular

Un framework front-end de Google, en TypeScript, pour construire des applications web d'une seule page (SPA) : l'interface est découpée en composants réutilisables, et la page se met à jour toute seule quand les données changent.

Composant

Une classe TypeScript décorée par @Component, avec un sélecteur (sa balise), un template (son HTML, dans templateUrl ou template) et des styles. Les propriétés de la classe sont les données affichées.

SyntaxeRôle
{{ valeur }}Interpolation : afficher une propriété
[propriété]="expr"Property binding : du composant vers le HTML
(événement)="méthode()"Event binding : réagir à un clic, une touche
[(ngModel)]="prop"Two-way binding (importer FormsModule)
*ngIf="cond"Afficher seulement si la condition est vraie
*ngFor="let x of liste"Répéter l'élément pour chaque x

Créer un composant : ng generate component taches (ou ng g c taches). Lancer : ng serve. Les versions récentes proposent aussi @if et @for à la place de *ngIf et *ngFor.

Chapitre 8 sur 8

Module 7 — Frameworks back-end : Laravel et Express

Un framework back-end fournit l'architecture MVC toute prête : Modèle (les données, la base), Vue (les pages), Contrôleur (la logique qui relie les deux), plus le routage, la sécurité, les migrations.

Laravel (PHP)

Eloquent (l'ORM) transforme chaque table en classe : Etudiant::all(), Etudiant::find(3), Etudiant::create([...]). Les vues Blade affichent avec {{ $e->nom }} (déjà protégé contre le XSS).

Express (Node.js)

Le duo moderne

Une API Express ou Laravel qui renvoie du JSON + un front Angular qui l'appelle avec HttpClient : c'est l'architecture de la plupart des applications web actuelles (et celle que tu verras en architecture logicielle).
