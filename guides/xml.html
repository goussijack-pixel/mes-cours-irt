Étape 1 – Le document n'est pas bien formé
Repère les erreurs avant d'écrire le schéma

Un XSD ne peut valider qu'un document bien formé. Celui du sujet ne l'est pas (vérifié avec un parseur XML : il est rejeté). Les erreurs :

  1. Espace après < ou </ : < styliste, </ marques >, </ couleur >… Un nom de balise doit suivre immédiatement le chevron.
  2. Guillemets typographiques ‘ ’ au lieu de " ou ' droits : type= ‘manche longue’.
  3. Les espaces dans les valeurs ("Alexandre JAPHET ") sont autorisés, mais inutiles : on les nettoie.

Étape 3 – Le schéma magasin.xsd

Comme description est la même dans les trois vêtements, on la définit une seule fois en type nommé : c'est le meilleur réflexe pour gagner des points.

Les 5 réflexes XSD
  1. Un élément avec enfants ou attributs a un complexType, sinon un type simple (xs:string, xs:integer…).
  2. Les attributs se déclarent après la séquence, dans le complexType.
  3. minOccurs="0" : optionnel ; maxOccurs="unbounded" : répétable.
  4. Texte et éléments mélangés : mixed="true".
  5. Une structure répétée devient un type nommé réutilisé avec type="…".
Piège classique

Un élément vide avec attributs (<manches …/>) reste un complexType, mais sans xs:sequence.

Module 0 — XML, c'est quoi ?

XML (eXtensible Markup Language)

Un format texte pour décrire des données structurées avec des balises que tu inventes : <etudiant>, <note>… Contrairement au HTML (balises imposées, pour l'affichage), XML sert à stocker et échanger des données entre programmes.

Tu en utilises sans le savoir : les fichiers Word (.docx) et Excel (.xlsx) sont des dossiers de fichiers XML ; Android décrit ses écrans en XML ; les flux RSS, le SVG, les configurations Maven (pom.xml) aussi.

Chapitre 2 sur 6

Module 1 — Un document bien formé

Les 6 règles du « bien formé »
  • Une seule racine qui contient tout.
  • Toute balise ouverte est fermée (<a>…</a> ou <a/>).
  • Les balises sont bien imbriquées : <a><b></b></a>, jamais <a><b></a></b>.
  • XML est sensible à la casse : <Nom> ≠ <nom>.
  • Les valeurs d'attributs sont entre guillemets droits "…" ou '…'.
  • Pas d'espace juste après < ou </, pas de caractère < ou & brut dans le texte (écrire &lt; et &amp;).
Les défauts volontaires du sujet « magasin »

Le document de l'examen contient < styliste, </ marques >, type= ‘manche longue’ (guillemets typographiques) : il n'est pas bien formé. Signale-le, puis construis le schéma sur la version corrigée (<styliste, </marques>, type="manche longue").

Bien formé ≠ valide

Bien formé : respecte la syntaxe XML. Valide : bien formé et conforme à une grammaire (DTD ou schéma XSD) qui dit quels éléments sont permis, dans quel ordre, combien de fois.

Module 3 — Le schéma XSD

Le schéma XML (XSD) est lui-même écrit en XML ; il apporte les types (entier, date, décimal…), des cardinalités précises et des contraintes.

Types simples et complexes
  • Type simple : du texte seul, sans enfant ni attribut : <xs:element name="nom" type="xs:string"/>.
  • Type complexe : un élément qui a des enfants et/ou des attributs : il faut un <xs:complexType>.
Balise XSDRôle
xs:schemaLa racine du schéma
xs:elementDéclare un élément (name, type, minOccurs, maxOccurs)
xs:complexTypeDécrit un élément avec enfants ou attributs
xs:sequenceEnfants dans cet ordre
xs:choiceUn enfant parmi plusieurs
xs:allTous, dans n'importe quel ordre (chacun au plus une fois)
xs:attributeDéclare un attribut (use="required" pour l'imposer)
mixed="true"Le type mélange texte et éléments
Construire un XSD à partir d'un document
  • Pars de la racine et descends niveau par niveau.
  • Chaque élément sans enfant ni attribut → xs:element avec un type simple (xs:string, xs:integer, xs:decimal, xs:date).
  • Chaque élément avec enfants ou attributs → xs:complexType, avec xs:sequence pour les enfants puis les xs:attribute (toujours après la séquence).
  • Un élément qui se répète → maxOccurs="unbounded".
  • Du texte mêlé à des balises (comme « 100% Coton » suivi de <couleur>) → mixed="true".
  • Un élément vide avec attributs → xs:complexType qui ne contient que des xs:attribute.

Le schéma du rattrapage : livre.xsd

Rendre le schéma lisible : les types nommés

Au lieu d'emboîter 8 niveaux, déclare <xs:complexType name="TChapitre">…</xs:complexType> au niveau du schéma, puis <xs:element name="chapitre" type="TChapitre" maxOccurs="unbounded"/>. Même résultat, beaucoup plus clair (et réutilisable).

Module 4 — Lier un document à son schéma

Espace de noms (namespace)

Un préfixe associé à une URI pour éviter les collisions de noms quand on mélange plusieurs vocabulaires (xs:element vient du vocabulaire XML Schema). L'URI est un identifiant, pas forcément une page web.

XML ou JSON ?

Aujourd'hui, les API web échangent surtout du JSON (plus léger). XML reste roi quand il faut des schémas stricts, des documents (bureautique, SVG) et dans beaucoup de systèmes d'entreprise et de banque.

Règles d'un XML bien formé

  • Une seule racine.
  • Toute balise ouverte est fermée (ou auto-fermante <x/>), et les balises sont bien imbriquées.
  • La casse compte : <A> est différent de <a>.
  • Les valeurs d'attributs sont entre guillemets droits "…" ou '…'.
  • Aucun espace juste après < ou </.
  • Les caractères spéciaux s'échappent : &lt; &gt; &amp; &quot;.
