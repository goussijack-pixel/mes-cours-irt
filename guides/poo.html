Corrigé détaillé

Essaie d’abord seul, puis ouvre chaque partie pour comparer.

Question 1 — POO et objet
Programmation orientée objet

Une façon de programmer où l’on représente le problème par des objets qui regroupent leurs données (attributs) et leurs comportements (méthodes), et qui communiquent entre eux. Ses quatre piliers : encapsulation, héritage, polymorphisme, abstraction.

Objet

Une entité concrète du programme, qui a un état (valeurs de ses attributs), un comportement (ses méthodes) et une identité (il est distinct des autres, même s’il leur ressemble). Ex. : le compte n° 0042 de Afi, solde 15 000 F.

Question 2 — classe et objet

La classe est le plan (le moule) ; l’objet est une réalisation de ce plan, une instance.

Image : le plan d’une maison (classe) et les maisons construites à Calavi et à Abomey (objets).

Question 3 — encapsulation

On cache les attributs (private) et on n’y accède que par des méthodes public qui contrôlent les modifications. Importance : empêcher des états absurdes (solde négatif), pouvoir changer l’intérieur de la classe sans casser le reste du programme, sécuriser.

Le retrait de 20 000 F est refusé par la classe elle-même : personne ne peut écrire c.solde = -500 depuis l’extérieur.

Question 4 — héritage

Une classe fille reprend les attributs et méthodes d’une classe mère et peut en ajouter ou en redéfinir. Mot-clé : extends. On l’utilise quand on peut dire « est un » : un Etudiant est une Personne, un CompteEpargne est un Compte.

Piège classique

Pas d’héritage quand la relation est « a un » (une voiture a un moteur) : là, on met un attribut (composition).

Question 5 — polymorphisme par surcharge

Le polymorphisme = une même opération (même nom) qui se comporte différemment selon le contexte. La surcharge (overloading) en est la forme statique : plusieurs méthodes de même nom avec des paramètres différents ; Java choisit à la compilation selon les arguments.

L’autre forme (dynamique) est la redéfinition (overriding) : une sous-classe réécrit une méthode héritée, et Java choisit à l’exécution selon l’objet réel (voir question 7).

Quand utiliser quoi : classe abstraite quand des classes de la même famille partagent du code et un état (Forme → Rectangle, Cercle) ; interface pour un contrat que des classes sans lien peuvent respecter (Imprimable, Comparable).

Question 7 — rôle des interfaces (exemple testé)

Une interface définit ce qu’on peut faire sans dire comment (abstraction). Toute classe qui l’implémente peut être manipulée par une variable du type de l’interface (polymorphisme).

La boucle for (Imprimable d : docs) d.imprimer(); ne sait pas si d est un rectangle ou un cercle : chaque objet exécute sa version. C’est le polymorphisme.

Chapitre 2 sur 7

Module 1 — Classe, objet, constructeur

Programmation orientée objet (POO)

Une façon de programmer où l'on modélise le problème sous forme d'objets qui regroupent leurs données (attributs) et leurs comportements (méthodes), et qui collaborent en s'envoyant des messages (appels de méthodes).

Objet

Une entité concrète du programme, qui a un état (les valeurs de ses attributs), un comportement (ses méthodes) et une identité (il est unique en mémoire, même si un autre a les mêmes valeurs).

Classe

Le modèle (le moule, le plan) qui décrit les attributs et les méthodes communs à tous les objets d'un même type. Un objet est une instance d'une classe.

L'image qui fait mouche à l'examen

La classe, c'est le plan d'architecte d'une maison ; les objets, ce sont les maisons construites à partir de ce plan. Un seul plan, plusieurs maisons, chacune avec sa propre couleur de façade.

Constructeur

Une méthode spéciale, appelée automatiquement à la création d'un objet (avec new), qui initialise ses attributs. En Java, il porte le nom de la classe et n'a pas de type de retour. En Python, c'est __init__(self, …).

this

this désigne l'objet courant. this.marque = marque veut dire : « mon attribut marque reçoit le paramètre marque ». Sans this, le paramètre cacherait l'attribut.

Chapitre 3 sur 7

Module 2 — Encapsulation et modificateurs d'accès

Encapsulation

Regrouper dans une classe les données et les méthodes qui les manipulent, et cacher les données (attributs private) pour qu'on ne puisse les modifier que par des méthodes contrôlées (getters, setters, méthodes métier).

Pourquoi c'est important
  • Protéger l'état de l'objet : impossible de mettre un solde négatif ou un âge de −5 ans.
  • Cacher l'implémentation : on peut changer l'intérieur de la classe sans casser le code qui l'utilise.
  • Faciliter la maintenance et éviter les bugs : une seule porte d'entrée pour chaque modification.

Sans encapsulation, n'importe quel code pourrait écrire c.solde = -1000000;. Avec, il doit passer par retirer, qui vérifie.

Chapitre 4 sur 7

Module 3 — L'héritage

Héritage

Un mécanisme qui permet de créer une nouvelle classe (fille, sous-classe) à partir d'une classe existante (mère, superclasse) : la fille récupère les attributs et méthodes de la mère, peut en ajouter et en redéfinir. En Java : extends. Relation « est un » : un Étudiant est une Personne.

Quand l'héritage est approprié

Quand il existe une vraie relation « est un » et du code commun à factoriser : Etudiant et Enseignant héritent de Personne ; CompteEpargne et CompteCourant héritent de Compte ; Cercle et Rectangle héritent de Forme. Avantages : réutilisation du code, moins de duplication, et c'est la base du polymorphisme.

Héritage ou composition ?

Une Voiture a un Moteur : ce n'est pas de l'héritage mais de la composition (un attribut Moteur moteur). Java n'autorise qu'une seule classe mère (extends), mais plusieurs interfaces (implements).

Chapitre 5 sur 7

Module 4 — Le polymorphisme

Polymorphisme

La capacité d'un même nom de méthode (ou d'une même référence) à se comporter différemment selon le contexte : selon les paramètres (surcharge) ou selon l'objet réel qui l'exécute (redéfinition). « Poly » = plusieurs, « morphe » = formes.

Surcharge (overloading)Redéfinition (overriding)
Où ?Dans la même classeDans une classe fille
SignatureMême nom, paramètres différents (nombre ou types)Même nom, mêmes paramètres
Choisie quand ?À la compilation (polymorphisme statique)À l'exécution, selon l'objet réel (dynamique)
Annotation–@Override

Polymorphisme par surcharge (question 5 du devoir)

Le même nom additionner réalise trois comportements ; Java choisit la bonne version selon les arguments.

Polymorphisme par redéfinition

La phrase clé

« Une référence de type parent peut désigner un objet fille, et c'est la méthode de l'objet réel qui s'exécute. » C'est ce qui permet de traiter différentes classes comme des instances de la superclasse.

Chapitre 6 sur 7

Module 5 — Abstraction : classe abstraite et interface

Abstraction

Cacher les détails complexes et ne montrer que les fonctionnalités nécessaires. Tu conduis une voiture avec un volant et des pédales sans connaître le moteur : c'est de l'abstraction.

Classe abstraite

Une classe déclarée abstract qu'on ne peut pas instancier (new Forme() est interdit). Elle peut contenir des attributs, des constructeurs, des méthodes concrètes et des méthodes abstraites (sans corps) que les filles doivent écrire.

Interface

Un contrat : une liste de méthodes que toute classe qui l'implémente (implements) s'engage à fournir. Pas d'attributs d'instance (seulement des constantes), et une classe peut implémenter plusieurs interfaces.

Mot-cléabstract class, extendsinterface, implements
Combien par classe ?Une seulePlusieurs
AttributsOui (état commun)Seulement des constantes (static final)

Quand utiliser l'une ou l'autre
  • Classe abstraite : des classes de la même famille partagent du code et des attributs (Forme → Cercle, Rectangle ; Compte → CompteCourant, CompteEpargne).
  • Interface : des classes sans lien de famille partagent une capacité (Payable pour un Salarié et une Facture ; Comparable ; Volant pour un Oiseau et un Avion), ou il faut un « héritage multiple ».
Rôle des interfaces (question 7)

Elles servent l'abstraction (on ne voit que ce que l'objet sait faire, pas comment) et le polymorphisme (une variable Payable peut contenir un Salarié ou une Facture, et montantAPayer() s'exécute différemment selon l'objet).

Les réponses du QCM en une ligne chacune
  • Regrouper données et méthodes / protéger l'état / cacher l'implémentation → encapsulation.
  • Dériver d'une classe / créer une classe à partir d'une autre → héritage.
  • Même fonction, comportement différent selon l'objet / traiter des classes comme la superclasse / même interface, manières différentes → polymorphisme.
  • Masquer les détails et ne montrer que l'utile / n'utiliser que les fonctionnalités nécessaires → abstraction.
  • Créer de nouveaux objets basés sur des objets existants → héritage (au sens du QCM).
  • Méthode spéciale appelée à la création → constructeur (__init__() en Python).
  • Classe = modèle, objet = instance.
Les 4 erreurs qui coûtent des points
  • Donner un constructeur avec un type de retour (void Voiture()) : ce n'est plus un constructeur.
  • Confondre surcharge (même classe, paramètres différents) et redéfinition (classe fille, même signature).
  • Dire qu'une interface « hérite » : une classe implémente une interface.
  • Oublier l'exemple concret : il vaut souvent la moitié des points.

Quiz

Mémo d’examen

L’essentiel à relire juste avant l’épreuve.

Les 4 piliers

Encapsulation (protéger) · Héritage (réutiliser, « est un ») · Polymorphisme (même appel, comportements différents) · Abstraction (montrer l’essentiel).

Surcharge ≠ redéfinition

Surcharge : même nom, paramètres différents, même classe. Redéfinition : même signature, sous-classe, @Override.

Abstraite vs interface

extends une seule classe abstraite (code + état commun) ; implements plusieurs interfaces (contrats).

Accès

private < (package) < protected < public.

Réflexes de copie

Attributs privés, constructeur avec this, getters/setters utiles seulement, règles métier dans les méthodes, equals pour les String.
