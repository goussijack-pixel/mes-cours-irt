Les chiffres clés du DNS
  • Structure en arbre inversé ; la racine est une chaîne vide (le point final d'un FQDN).
  • Une étiquette fait 63 caractères au maximum ; un nom complet, 255.
  • Trois sections : domaines génériques (.com, .org), nationaux (.bj, .fr), inversé (in-addr.arpa).
  • Le primaire charge sa zone depuis ses fichiers ; le secondaire la copie par transfert de zone.
Récursif ou itératif
  • Récursif : « donne-moi la réponse finale ». C'est le client qui interroge son serveur DNS.
  • Itératif : « je ne sais pas, va voir ce serveur-là ». C'est le serveur qui interroge la racine, puis le TLD.
Questions 20 et 23

Q20 : « Les noms génériques commencent par » est mal formulé ; la réponse attendue est \* (le caractère générique, wildcard). Q23 : les énoncés A, B et C sont tous vrais (un nom peut avoir plusieurs IP, et inversement), donc « aucune n'est fausse » : D.

À retenir

Le critère de choix numéro 1 est le nombre de machines virtuelles : peu de VM ⇒ Standard ; beaucoup ⇒ Datacenter.

Q3 – Prérequis matériels (minimums)
  • Processeur : 64 bits à 1,4 GHz, avec NX/DEP, CMPXCHG16b, LAHF/SAHF, PrefetchW, et SLAT pour Hyper-V.
  • Mémoire vive : 512 Mo (Server Core), 2 Go avec l'interface graphique (Expérience utilisateur), de préférence ECC.
  • Disque : 32 Go minimum.
  • Réseau : carte Ethernet, au moins gigabit recommandé.
  • Optionnel : UEFI 2.3.1c avec Secure Boot, puce TPM 2.0.
Q4 à Q7 – Réponses courtes
  • Q5 : RSAT (Remote Server Administration Tools).
  • Q6 : la pré-création (pré-intégration, prestaging) du compte d'ordinateur.
  • Q7 : la console Sites et services Active Directory (dssite.msc) : on crée des sites et on y associe des sous-réseaux.
Q8 et Q9 – Stratégies de groupe

Q8 : une stratégie de groupe (GPO) est un ensemble de paramètres de configuration (sécurité, bureau, logiciels, scripts…) appliqués automatiquement aux utilisateurs et aux ordinateurs d'un site, d'un domaine ou d'une OU. Elle permet une gestion centralisée du parc.

Q9 : la Default Domain Policy, liée à la racine du domaine. Elle contient la stratégie de mots de passe : longueur, complexité, durée de vie, verrouillage.

11Les points de contrôle (checkpoints, anciennement snapshots).

Q14, Q15 et Q17 – WSUS

Éléments de WSUS (Q14) :

  • le serveur WSUS (rôle + service web IIS + base WID ou SQL Server + dossier de contenu) ;
  • la console d'administration ;
  • les clients, c'est-à-dire l'agent Windows Update configuré par GPO ;
  • les groupes d'ordinateurs (test, production…) ;
  • éventuellement des serveurs en amont / en aval (hiérarchie).

Configuration logicielle (Q15) : Windows Server, rôle IIS, .NET Framework 4.x, base WID (interne) ou SQL Server, et Report Viewer pour les rapports.

Pour monter WSUS (Q17) :

  • un serveur membre du domaine ;
  • un volume NTFS avec assez d'espace (≥ 40 Go conseillés) ;
  • un accès à Microsoft Update (ou à un WSUS amont) ;
  • les ports 8530/8531 ouverts ;
  • une GPO qui indique aux clients l'adresse du serveur WSUS.
Q16, Q19 et Q20 – WDS
  • Q16 : WDS (Windows Deployment Services), avec démarrage réseau PXE.
  • Q19 : si DHCP et WDS sont sur le même serveur, il faut configurer l'option 60 (PXEClient) et cocher « ne pas écouter sur le port 67 ». S'ils sont sur deux serveurs différents, on utilise les options 66 (serveur de démarrage) et 67 (fichier de démarrage), ou un relais (IP helper).
  • Q20 : une image de capture est une image de démarrage spéciale (WinPE). Elle lance l'assistant de capture pour enregistrer, au format .wim, l'image d'un ordinateur de référence préalablement généralisé avec Sysprep. Cette image servira ensuite d'image d'installation.
Q18 – Déployer un correctif en urgence
  1. 1. Identifier le bulletin et le KB du correctif ; isoler les machines infectées.
  2. 2. Synchroniser WSUS avec Microsoft Update pour récupérer le correctif.
  3. 3. Approuver le correctif d'abord pour un groupe de test, vérifier, puis pour tous les groupes, avec une échéance (installation forcée).
  4. 4. Par GPO, imposer l'installation automatique et le redémarrage.
  5. 5. Suivre les rapports WSUS (taux d'installation, échecs) et traiter les machines en retard.
À retenir

En urgence, l'échéance (deadline) dans WSUS force l'installation même si l'utilisateur la repousse.

Le bail DHCP
  • À 50 % du bail, le client demande un renouvellement en unicast au serveur qui lui a donné l'adresse.
  • À 87,5 %, il envoie un REQUEST en diffusion à n'importe quel serveur : c'est la phase de « rebinding ».

Écrire le nom d'une zone inversée

Pour le réseau 172.16.35.0/24, on écrit les octets à l'envers et on ajoute .in-addr.arpa, ce qui donne 35.16.172.in-addr.arpa (Q29).

Sécurité DNS sous Windows Server
  • Verrouillage du cache : empêche d'écraser une entrée du cache avant un certain pourcentage de son TTL (Set-DnsServerCache -LockingPercent 100).
  • Pool de sockets : rend aléatoires les ports source des requêtes, contre l'empoisonnement du cache.
  • DNSSEC : signature des zones.
  • DANE : publie des certificats TLS dans des enregistrements TLSA.
  • DNS partagé (split-brain) : un même nom de domaine pour l'interne et l'externe, avec des réponses différentes.

Q35 : les stratégies DNS permettent de répondre selon le sous-réseau du client (filtrage ou gestion du trafic par localisation). Q40 : aucune option ne désigne vraiment un type d'enregistrement de stratégie. RRL (Response Rate Limiting) est la seule fonctionnalité de « politique » de réponse proposée.

Les 5 rôles FSMO
  • Pour toute la forêt : maître de schéma (modifie le schéma), maître d'attribution des noms de domaine (ajoute ou retire des domaines).

  • E. La gestion des adresses IP devient complexe et sujette aux erreurs.

2

Corrigé détaillé

Essaie d’abord seul, puis ouvre chaque partie pour comparer.

A – DHCP et DNS

1. Configuration

  • DHCP : une étendue par site / sous-réseau, avec des plages qui ne se chevauchent pas ; un basculement DHCP (failover) entre deux serveurs, en mode équilibrage de charge ou serveur de secours ; un relais DHCP (IP helper) sur les routeurs.
  • DNS : des zones intégrées à Active Directory (réplication sécurisée), un serveur DNS par site (souvent sur le contrôleur de domaine local), des redirecteurs (ou redirecteurs conditionnels) vers l'extérieur, et les mises à jour dynamiques sécurisées activées.

2. Mesures précises

  • Conflits d'adresses : exclure de l'étendue les adresses fixes (serveurs, imprimantes) ; utiliser des réservations plutôt que des IP saisies à la main ; activer la détection de conflit (le serveur fait un ping avant d'attribuer une adresse) ; interdire les IP manuelles par GPO et procédure ; ne garder qu'un seul serveur DHCP autorisé par étendue (les serveurs pirates sont bloqués grâce à l'autorisation dans AD).
  • Performances DNS : activer le vieillissement et le nettoyage (scavenging) des enregistrements obsolètes ; laisser le client interroger d'abord le DNS de son site ; régler le cache ; surveiller avec dcdiag /test:dns et les journaux DNS.
B – BranchCache

1. Principe : le premier client d'une agence télécharge le fichier depuis le siège, puis le met en cache. Les clients suivants le récupèrent localement, ce qui économise la liaison WAN. Le serveur ne vérifie que les hachages (identifiants du contenu) pour garantir que le fichier est à jour.

2. Mode distribué (cache réparti entre les postes, sans serveur dans l'agence)

  1. 1. Serveur de fichiers du siège : installer la fonctionnalité BranchCache pour fichiers réseau (Install-WindowsFeature FS-BranchCache).
  2. 2. Par GPO (Modèles d'administration > Réseau > Serveur Lanman), activer la publication des hachages pour BranchCache, puis activer BranchCache sur les partages concernés.
  3. 3. Clients : par GPO (Réseau > BranchCache), activer BranchCache, choisir le mode Cache distribué et définir la taille du cache.
  4. 4. Pare-feu : ouvrir les règles BranchCache (HTTP 80 pour la récupération, WS-Discovery UDP 3702 pour la découverte).
  5. 5. Vérifier avec Get-BCStatus et surveiller l'utilisation du WAN.

D – Consolidation avec Hyper-V

1. Avantages

  • moins de serveurs physiques : moins d'énergie, de climatisation, d'espace et de maintenance ;
  • meilleure utilisation du matériel ;
  • déploiement rapide (modèles de VM) ;
  • points de contrôle avant les mises à jour ;
  • haute disponibilité (cluster de basculement, migration dynamique) ;
  • Hyper-V Replica pour le plan de reprise ;
  • isolation des services ;
  • licences Datacenter : VM Windows illimitées.

2. Plan de migration

  1. 1. Inventaire : rôles, charge (CPU, RAM, E/S), dépendances. On classe les services par criticité.
  2. 2. Préparer les hôtes Hyper-V (de préférence en cluster, avec stockage partagé), les commutateurs virtuels et les sauvegardes.
  3. 3. Migrer d'abord les services peu critiques : conversion physique vers virtuel (outils P2V, ou disques VHDX), ou réinstallation propre sur une VM neuve.
  4. 4. Services critiques : pour AD, DNS et DHCP, on ajoute de nouveaux serveurs virtuels (nouveau DC, basculement DHCP), puis on retire les anciens. Pas de P2V d'un contrôleur de domaine. Pour les serveurs de fichiers : copie avec Robocopy et bascule DFS. On travaille hors des heures de production.
  5. 5. Tests de fonctionnement et plan de retour arrière (l'ancien serveur reste éteint mais disponible quelques jours).
  6. 6. Mise en service de Hyper-V Replica et des sauvegardes de VM ; documentation.
E – IPAM

1. Apports : une console centrale qui découvre automatiquement les serveurs DHCP et DNS, surveille l'utilisation des étendues (alertes de saturation), gère les plages, les réservations et les zones depuis un seul endroit, et garde un historique et un audit (qui avait quelle adresse, et quand). On abandonne ainsi les fichiers Excel source d'erreurs.

2. Déploiement

  1. 1. Installer la fonctionnalité IPAM sur un serveur membre (pas sur un contrôleur de domaine).
  2. 2. Provisionner IPAM : méthode par GPO (recommandée), avec un préfixe de GPO.
  3. 3. Créer les GPO d'accès : Invoke-IpamGpoProvisioning -Domain tech.local -GpoPrefixName IPAM -IpamServerFqdn ipam.tech.local.
  4. 4. Découvrir les serveurs (contrôleurs de domaine, DHCP, DNS) puis les marquer comme gérés.
  5. 5. Récupérer les données ; organiser l'espace d'adresses par site ; configurer les alertes de seuil.
  6. 6. Ensuite, gérer les étendues DHCP et les zones DNS depuis la console IPAM (gestion centralisée), avec délégation de rôles (administrateur IPAM, administrateur DHCP…).

La stratégie AGDLP

Accounts (comptes) → Global groups (groupes globaux, par métier) → Domain Local groups (groupes de domaine local, par ressource) → Permissions (droits). Les autorisations sur les ressources se donnent donc aux groupes de domaine local (Q14).

Canal sécurisé rompu (Q17 à Q19)

Chaque ordinateur du domaine a un mot de passe de compte machine, stocké comme secret LSA et changé automatiquement. S'il diverge de celui d'AD (restauration d'une vieille image, par exemple), la relation d'approbation est rompue. On la répare avec Test-ComputerSecureChannel -Repair, netdom resetpwd ou nltest /sc_reset, ou en sortant puis en remettant le poste dans le domaine.

Questions discutables
  • Q3 : la réplication intersites peut utiliser IP (RPC) ou SMTP. La réplication intrasite utilise aussi RPC sur IP. La réponse attendue est l'intersites.
  • Q5 : le niveau fonctionnel de domaine 2012 introduit le blindage Kerberos (Kerberos armoring, FAST). Les silos d'authentification arrivent en 2012 R2.
  • Q25 : les extensions côté client (CSE) appliquent les paramètres. Celle du registre applique les modèles d'administration, le cas le plus courant.
Étude de cas – 1a et 1b : structure des OU

Justification des OU

  • une OU par site : on peut déléguer l'administration locale (réinitialiser les mots de passe) au technicien de la succursale ;
  • on sépare utilisateurs et ordinateurs : les GPO utilisateur et ordinateur sont différentes ;
  • des sous-OU par service (comptabilité, commercial) : GPO et droits par métier ;
  • des sous-OU par type de poste (portables : BitLocker, VPN ; postes fixes) ;
  • une OU Serveurs : stratégies durcies, calendrier WSUS propre ;
  • les comptes ne restent pas dans les conteneurs par défaut Users et Computers, sur lesquels on ne peut pas lier de GPO (d'où redircmp et redirusr).

Rôle des deux serveurs : le serveur principal est DC, DNS, DHCP et WSUS ; le serveur de sauvegarde est un second DC avec DNS et partenaire de basculement DHCP. Il assure la haute disponibilité et la sauvegarde.

Étude de cas – 1c : relations d'approbation
  • Elles permettent aux utilisateurs d'un domaine d'accéder aux ressources d'un autre domaine sans second compte.
  • Dans une même forêt, les approbations parent-enfant et racine d'arborescence sont bidirectionnelles et transitives, créées automatiquement.
  • Entre forêts (fusion, partenaire), on crée des approbations de forêt ou externes, avec filtrage des SID et authentification sélective.
  • Les approbations raccourcies accélèrent l'authentification entre domaines éloignés de l'arbre.

Sans approbations correctement définies, une infrastructure distribuée sur plusieurs sites et domaines ne peut pas partager ses ressources de façon sûre.

Étude de cas – 2a : configuration initiale de DHCP et DNS
  • DNS intégré à AD : la réplication est automatique et sécurisée, les enregistrements SRV permettent aux postes de trouver les DC. Sans DNS fiable, ni ouverture de session ni GPO ne fonctionnent.
  • DHCP : il distribue de façon cohérente l'IP, le masque, la passerelle (option 003), les serveurs DNS (006) et le suffixe (015). Résultat : aucune erreur de saisie, et un changement se fait en un seul endroit.
  • La mise à jour DNS dynamique par DHCP garde les enregistrements A et PTR à jour.
Étude de cas – 2b : éviter les conflits et fiabiliser le DNS
  1. Plan d'adressage documenté : plage statique pour les serveurs exclue de l'étendue ; réservations pour les imprimantes.
  2. Serveur DHCP autorisé dans AD (les serveurs pirates sont bloqués) et détection de conflit activée (1 ou 2 pings).
  3. Basculement DHCP entre les deux serveurs (équilibrage 50/50 ou secours).
  4. Deux serveurs DNS par client (le principal, puis la sauvegarde) ; redirecteurs vers l'extérieur ; vieillissement et nettoyage des enregistrements.
  5. Surveillance avec IPAM, dcdiag /test:dns et les journaux d'événements.

L’essentiel à relire juste avant l’épreuve.

Active Directory

  • Forêt > arborescence > domaine > OU > objets (utilisateurs, ordinateurs, groupes).
  • FSMO : pour la forêt, maître de schéma et maître d'attribution des noms de domaine ; pour chaque domaine, maître RID, émulateur PDC (heure, mots de passe) et maître d'infrastructure.
  • AGDLP : Comptes → groupes Globaux → groupes de Domaine Local → Permissions.
  • GPO : Local → Site → Domaine → OU (la dernière l'emporte). La Default Domain Policy contient la stratégie de mots de passe.
  • Corbeille AD : niveau fonctionnel 2008 R2 minimum ; Enable-ADOptionalFeature 'Recycle Bin Feature'. Son activation est irréversible.
  • RODC : contrôleur de domaine en lecture seule, pour les sites peu sûrs.
